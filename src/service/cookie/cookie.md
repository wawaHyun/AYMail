# 클릭커 게임 기획서 — Clicker Project

Next.js와 TypeScript를 사용해 **클릭으로 재화를 모으고, 업그레이드로 자동 생산량을 늘리는 웹 클릭커 게임**을 만드는 계획입니다.

이번 프로젝트의 목표는 처음부터 큰 게임을 만드는 것이 아니라, 작지만 완성된 게임을 먼저 만들고 이후 기능을 확장하는 것입니다. 서버와 데이터베이스는 사용하지 않고 브라우저에서 실행되는 MVP부터 시작합니다.

## 1. 게임 콘셉트

- **게임명(가칭):** CLICKER: Infinite Growth
- **장르:** 숫자 성장형 클릭커
- **플레이 방식:** 싱글 플레이, 클릭과 자동 생산 혼합
- **플랫폼:** 웹 브라우저

플레이어는 클릭으로 코인을 모으고, 업그레이드를 구매해 더 많은 코인을 생산합니다. 코인이 늘어날수록 더 비싼 업그레이드를 구매할 수 있고, 성장 속도도 점점 빨라집니다.

핵심 요소:
- **직접 클릭:** 클릭할 때마다 코인 획득
- **자동 생산:** 초당 코인 획득
- **업그레이드:** 클릭 획득량과 자동 생산량 강화
- **자동 저장:** 브라우저에 진행 기록 저장

## 2. MVP 기능 범위

MVP는 게임을 시작해서 성장하고, 저장한 뒤 다시 접속해 이어서 플레이할 수 있는 수준으로 정의합니다.

| 기능 | 상세 내용 | 우선순위 |
|---|---|---|
| 코인 클릭 | 클릭할 때마다 코인 증가 | 필수 |
| 클릭 강화 | 클릭당 획득량 증가 | 필수 |
| 자동 생산 | 초당 코인 자동 획득 | 필수 |
| 생산 업그레이드 | 자동 생산량 증가 | 필수 |
| 구매 비용 증가 | 같은 업그레이드를 살수록 가격 상승 | 필수 |
| 코인 부족 처리 | 구매 버튼 비활성화 | 필수 |
| 자동 저장 | 코인과 업그레이드 상태 저장 | 필수 |
| 오프라인 보상 | 게임을 닫은 동안의 일부 생산량 지급 | 선택 |
| 업적·랭킹·로그인 | 추가 콘텐츠 및 서버 기능 | 제외 |

**첫 번째 완성 목표:** 클릭, 업그레이드 구매, 자동 생산, 저장 기능이 모두 정상적으로 작동하는 게임입니다.

## 3. 게임 진행 구조

핵심 게임 루프:

1. **클릭해서 코인 획득** — 클릭 1회당 +1 코인부터 시작
2. **업그레이드 구매** — 클릭 강화 또는 자동 생산 시설 구매
3. **생산 속도 증가** — 직접 클릭하지 않아도 코인 축적
4. **더 비싼 업그레이드 구매** — 성장 → 구매 → 더 빠른 성장 반복

코인이 부족하면 직접 클릭하거나 자동 생산을 기다립니다.

### 초기 게임 밸런스

다음 수치는 실제 테스트 전의 초기 설정값입니다.

| 항목 | 초기값 | 효과 |
|---|---:|---|
| 보유 코인 | 0 | 시작 재화 |
| 클릭당 획득량 | 1 | 클릭 1회당 +1 |
| 자동 생산량 | 0/초 | 자동 생산 업그레이드로 증가 |
| 클릭 강화 첫 가격 | 10 | 클릭당 획득량 +1 |
| 자동 생산 첫 가격 | 25 | 초당 생산량 +1 |
| 업그레이드 가격 증가율 | ×1.5 | 구매할 때마다 가격 상승 |

가격 계산:

`다음 가격 = floor(기본 가격 × 1.5 ^ 구매 횟수)`

예를 들어 클릭 강화 가격은 10 → 15 → 22 → 33 코인으로 증가합니다.

이렇게 하면 초반에는 직접 클릭하는 것이 중요하고, 나중에는 자동 생산이 성장의 중심이 됩니다.

## 4. 화면 구성

처음에는 화면 하나에 모든 기능을 배치합니다.

### 상단 상태
- 보유 코인
- 클릭당 획득량
- 초당 생산량

### 중앙 클릭 영역
- 가장 눈에 띄는 코인 버튼
- 클릭 시 코인 획득
- 터치하기 쉽도록 큰 버튼으로 제작

### 하단 상점
- 업그레이드 이름
- 업그레이드 효과
- 현재 가격
- 구매 버튼

모바일에서도 사용할 수 있도록 화면 너비에 맞춰 배치합니다. 코인 숫자와 생산량은 상단에 모으고, 중앙 클릭 버튼과 하단 상점이 명확히 구분되도록 구성합니다.

## 5. Next.js 컴포넌트 구성

처음에는 페이지 하나와 컴포넌트 몇 개로 시작합니다. 컴포넌트를 너무 잘게 나누지 않습니다.

```text
src/
├── app/
│   ├── layout.tsx
│   ├── page.tsx
│   └── globals.css
├── components/
│   ├── GameHeader.tsx
│   ├── ClickButton.tsx
│   ├── UpgradeShop.tsx
│   └── UpgradeItem.tsx
├── hooks/
│   └── useGame.ts
├── types/
│   └── game.ts
└── data/
    └── upgrades.ts
```

| 파일 | 역할 |
|---|---|
| `page.tsx` | 게임 화면 조립 |
| `GameHeader.tsx` | 코인과 생산량 표시 |
| `ClickButton.tsx` | 코인 클릭 처리 |
| `UpgradeShop.tsx` | 업그레이드 목록 표시 |
| `UpgradeItem.tsx` | 업그레이드 1개와 구매 버튼 |
| `useGame.ts` | 코인, 생산량, 구매 로직 관리 |
| `game.ts` | TypeScript 타입 정의 |
| `upgrades.ts` | 업그레이드 기본 데이터 |

`useGame.ts`는 게임 규칙을 담당하고, 컴포넌트는 화면을 표시하는 역할을 맡습니다. 이렇게 분리하면 나중에 기능을 추가할 때 수정 범위를 줄일 수 있습니다.

### 게임 데이터 설계

```ts
type GameState = {
  coins: number;
  clickPower: number;
  coinsPerSecond: number;
  upgrades: Record<string, number>;
};
```

- `coins`: 현재 보유 코인
- `clickPower`: 클릭당 획득량
- `coinsPerSecond`: 초당 자동 생산량
- `upgrades`: 업그레이드별 구매 횟수

업그레이드 정보는 별도 데이터로 관리합니다.

```ts
type Upgrade = {
  id: string;
  name: string;
  baseCost: number;
  effect: number;
  type: 'click' | 'production';
};
```

업그레이드 종류가 늘어나더라도 데이터만 추가하면 상점에서 같은 컴포넌트를 재사용할 수 있습니다.

## 6. 단계별 개발 순서

### 1단계. 화면과 기본 클릭
- Next.js 프로젝트 생성
- 게임 화면과 코인 숫자 표시
- 버튼을 클릭하면 코인 증가
- 클릭당 획득량 표시

**완료 기준:** 클릭할 때마다 숫자가 정확히 증가합니다.

### 2단계. 업그레이드 구매
- 클릭 강화 업그레이드
- 코인 차감과 가격 증가
- 코인이 부족하면 구매 불가
- 구매 후 클릭 획득량 변경

**완료 기준:** 구매 전후의 코인과 획득량이 일치합니다.

### 3단계. 자동 생산
- 초당 생산량 업그레이드
- 일정 시간마다 코인 증가
- 클릭과 자동 생산의 동시 작동 확인

**완료 기준:** 클릭하지 않아도 코인이 증가합니다.

### 4단계. 저장과 불러오기
- `localStorage`에 게임 상태 저장
- 페이지를 새로고침해도 진행 상태 유지
- 저장 데이터가 없을 때 초기값 사용

**완료 기준:** 새로고침 후에도 코인과 업그레이드가 유지됩니다.

### 5단계. 밸런스와 마무리
- 코인 숫자에 천 단위 구분자 적용
- 클릭 애니메이션 추가
- 가격과 생산량 밸런스 조정
- 모바일 레이아웃 점검

**완료 기준:** 처음부터 일정 시간 플레이해도 진행이 막히지 않습니다.

## 7. 구현할 때 주의할 점

### ① 자동 생산은 실제 경과 시간을 기준으로 계산

브라우저 탭이 비활성화되면 타이머가 늦어질 수 있습니다. 경과 시간에 초당 생산량을 곱하면 이를 더 정확하게 처리할 수 있습니다.

`획득 코인 = 초당 생산량 × 경과 시간(초)`

### ② `localStorage`는 서버 컴포넌트에서 직접 사용하지 않기

`localStorage`는 브라우저에서만 접근할 수 있으므로 게임 상태를 관리하는 클라이언트 컴포넌트나 커스텀 훅에서 사용합니다. 저장된 데이터를 불러오기 전에는 초기 상태와의 불일치도 주의해야 합니다.

### ③ 저장 기능을 처음부터 복잡하게 만들지 않기

MVP에서는 계정, 서버 API, DB가 필요하지 않습니다. 브라우저별로 독립적인 저장만 지원하면 충분합니다.

## 8. MVP 완료 후 확장 아이디어

- **오프라인 보상:** 접속하지 않은 시간에 비례해 코인 지급
- **새로운 생산 시설:** 채굴기, 공장, 발전소 등 추가
- **업적:** 누적 클릭 횟수와 총 생산량에 따른 보상
- **환생 시스템:** 일정 조건에서 진행도를 초기화하고 영구 보너스 획득
- **통계:** 누적 코인, 총 클릭 수, 최고 생산량 기록

환생 시스템은 클릭커 게임의 장기 목표를 만드는 데 유용하지만, 첫 버전에는 넣지 않는 편이 좋습니다.

## 9. 최종 개발 계획

| 항목 | 결정 |
|---|---|
| 프레임워크 | Next.js |
| 언어 | TypeScript |
| 스타일 | Tailwind CSS |
| 상태 관리 | React `useState` 또는 `useReducer` |
| 저장 | `localStorage` |
| 서버·DB | MVP에서는 사용하지 않음 |
| 개발 순서 | 클릭 → 구매 → 자동 생산 → 저장 → 밸런스 |

**첫 번째 작업은 `page.tsx`에서 코인 숫자와 클릭 버튼을 구현하는 것입니다.** 처음부터 모든 파일을 만들지 말고, 클릭 기능이 정상 작동한 뒤 `useGame.ts`와 상점 컴포넌트를 분리합니다. 이 프로젝트는 완성 후 기능을 확장하기 쉽고, React 상태 관리와 게임 로직을 함께 연습하기에도 적합합니다.
